    4. Pihole Web Interface Login & Checks

    Next, is logging into the Pihole Interface, and a quick overview of what we can do, and the settings available to us.

    IP & Local Domain

    To first load up the Pihole Interface, we will need to enter your IP Address in the Address Bar. Example being: http://192.168.x.x:${PORT}

    With Nginx, we can set this up against a local domain, something like https://pihole.user.local, with HTTPS enabled with self-signed certs. You can find how these were setup via [Insert guide links], but for the time being, after initial setup without Nginx and Self-Signed Certs, the IP Address mentioned above will allow you onto the login page with HTTP.

    Main Portal Page

    Once loaded, we will be presented with the login page. Enter the password setup from the installation guide [1. Installation], which was set on the compose file.

    ![[Pasted image 20260815162538.png|394]]

    Once logged in, we will be presented with the main dashboard. This will show the current status, total queries made, queries blocked, and client activity. We can also view the Upstream Servers widget, which shows which servers are actioning the queries.

    We can specifically click on certain widgets on the dashboard, such as Total Queries, which will take us to the report, and also provide live feeds of what's coming in.

    Unbound Checks

    On the Dashboard, find the Upstream Servers widget, and check over which upstream servers are appearing:

    ![[Pasted image 20260815162849.png|397]]

    We can see for example, that our Unbound DNS is working, as it is showing with private IP Address 172.21.0.2#53, which is used by the Unbound Docker container (Docker containers usually use 172.x.x.x). Inside the docker container itself, it will be using IP 127.0.0.1.

    These next settings should be set automatically by the installation, but good to check anyway. Under Settings > DNS, untick all Upstream DNS Servers, and add on the Unbound custom DNS as so:

    In the same area, also set Interface settings to 'Permit all origins'. **Note: As mentioned, this may be set already by the Compose file. If so, this will be greyed out, and you cannot change it. This would only be changeable by amending the Compose file, and re-creating the Docker container.

    This setting needs to be set to 'Permit all origins', as this allows both our Pihole and Unbound docker containers to communicate with each other. This is due to them both using separate docker networks, showing as this they're coming from outside the local subnet.

    We can lastly run two commands in the console, to check that it is returning our container's 172.x.x.x IP as the DNS Domain:

    # Check if Pihole is using Unbound
docker exec -it pihole nslookup example.com unbound

# Test from another device
nslookup example.com 192.168.x.x

    Both should return the following:

    unbound

    Server: unbound
Address: 172.21.0.3#53

Non-authoritative answer:
Name: example.com
Address 104.20.32.154

    192.168.x.x

    Server: 192.168.x.x
Address: 192.168.x.x#53

Non-authoritative answer:
Name: example.com
Address: 172.66.147.243

    The unbound block will show 172.x.x.x if successful, showing that it is using the docker IP for the unbound container.

    The 192.168.x.x will show the same IP if successful, showing that your external device is successfully reaching Pihole.
