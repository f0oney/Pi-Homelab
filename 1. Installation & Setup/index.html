    1. Installation & Setup

    Vaultwarden is used to locally host your own Bitwarden Password Manager. This will be installed via a Docker Compose installation.

    Docker Compose Creation

    Firstly, we can create out .yaml compose file under directory ~/pihomelab/docker-compose The following is to be entered on the file:

    sudo nano vaultwarden-compose.yaml

    services:
  vaultwarden:
    image: vaultwarden/server:latest
    container_name: vaultwarden
    restart: unless-stopped
    dns:
      - 172.21.0.3 # To ensure Vaultwarden uses Unbound (Docker IP)
      - 192.168.50.44 # Fallback to Pi IP as DNS
    networks:
      dns_network:
    environment:
      DOMAIN: ${DOMAIN}  # enter your domain
      SIGNUPS_ALLOWED: "false"                  # disable after creating your first account
      ADMIN_TOKEN: ${ARGON2_HASH}
    volumes:
      - ${VAULTWARDEN_VOLUME}:/data

networks:
  dns_network:
    external: true
    driver: bridge

    networks: - Connected to our docker network, allowing for DNS communication, and working alongside Nginx.

    Admin Token

    For 'ADMIN_TOKEN', as we're hosting this file on Github, I have created a .env file to keep this on, with ${ARGON2_HASH} being called from it.

    Under the same directory, I have ran sudo nano .env, and added the following inside:

    ARGON2_HASH='INSERT_HASH_HERE'
DOMAIN=vault.user.local

    Generating encrypted ARGON2 Hash

    To obtain and securely generate the ARGON2 hash code, we can generate a PHC code using Bitwarden defaults. There are a few methods of doing this, but the simplest is creating a temporary docker container:

    docker run --rm -it vaultwarden/server:latest /vaultwarden hash

    This will prompt for a password upon running the command; Enter a secure password (this will be your admin password). The output will then generate something similar to this:

    $argon2id$v=14$n=233421,t=3,p=8$kK31413FFEsfCxSDdddwCF9LYXqrP312WERWgh2asdaff3E8ozeV+fsf324fgg5aJrRax4324fDVVDns8M

    Paste what is generated into the env file, but making sure the single quotes are used at the start and end of the token.

    Once the compose file is setup and ready, and setting the port number to be used, we can run the installation:

    sudo docker compose -f vaultwarden-compose.yaml up -d

    HTTPS Setup

    As Vaultwarden requires HTTPS to function, and allow you onto the vault, we have to make sure this is setup on our reverse proxy, Nginx.

    Please refer to [Vaultwarden Server Block], and HTTPS steps breakdown via [4. HTTPS Configuration].

    Initial Setup

    Once HTTPS is setup, we can proceed on creating our login. On the browser, enter address vault.user.local.

    On loading up the webpage, you will be presented with the Vaultwarden login interface. As this is a selfhosted Bitwarden vault, you won't be able to use an existing Bitwarden account. Therefore, we will need to create a new login.

    Click Create Account, and setup your login.

    Exporting and Importing Passwords

    Once in, we can import our passwords. If you have password stored on a normal Bitwarden account, you can export these via the portal to a .json file.

    Export
    1. Navigate to Tools > Export
    2. Select file format .json
    3. Press Export, and select the area on your machine you'd like to store the file on
    Import
    1. Navigate to Tools > Import
    2. Under Destination, select My vault, and leave the folder blank
    3. Under Data, select file format Bitwarden (json), and click Choose file
    4. Select the .json file on your machine, and press Import

    When imported, all passwords should successfully transfer onto the account.

    Updating Vaulwarden

    As for all docker containers, please ensure that the containers are updated with the latest image!!

    We can tell if it is out-of-date, due to the browser extensions, mobile app, and desktop app of Bitwarden are not successfully pulling the passwords, and can also be checked via https://vault.user.local/admin/diagnostics.

    Simply run the command below to pull the latest image, and then stop the container, delete the container, and reinstall it again from the compose.yaml file:

    docker pull vaultwarden/server:latest
