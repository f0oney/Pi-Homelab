    3. Deploying to Github Pages

    As it is running in a container, and we need to run mkdocs gh-deploy, we will need to run this inside the container via:

    docker exec docker-compose-mkdocs-1 mkdocs gh-deploy

    docker-compose-mkdocs-1 being the container name, followed by the command itself.

    Initialize the Host SSH Agent and Load Keys

    Start your host SSH agent and load your private key so your passphrase is cached in memory. Verify that the agent successfully holds the identity and check your active socket path.

    eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
ssh-add -l
echo $SSH_AUTH_SOCK

    Configuring the Docker Compose File

    Modify your mkdocs-compose.yml to mount your local repository, your host .ssh folder as read-only (:ro), and your SSH agent socket.

    services:
  mkdocs:
    image: squidfunk/mkdocs-material
    ports:
      - "8005:8000"
    dns:
      - ${UNBOUND_DOCKER_IP} # Points to your Unbound
      - ${PI_IP}
    volumes:
      - ~/pihomelab:/docs
      - ~/.ssh:/root/.ssh:ro # Points to the keys and knownhosts
      - ${SSH_AUTH_SOCK}:/ssh-agent # Our ssh agent used for the passkey. /tmp/ is 
    environment:
      - SSH_AUTH_SOCK=/ssh-agent
    stdin_open: true
    tty: true

    Verify Container File Access

    Confirm that the running container can correctly read your mounted keys and known hosts directory from inside the file system.

    docker exec docker-compose-mkdocs-1 ls -la /root/.ssh

    Test GitHub Authentication Inside the Container

    Verify that the container can successfully authenticate against GitHub using the mapped SSH agent and known hosts file.

    docker exec docker-compose-mkdocs-1 ssh -o UserKnownHostsFile=/root/.ssh/known_hosts -T git@github.com

    Expected response: Hi username! You've successfully authenticated, but GitHub does not provide shell access.

    Test General GitHub Authentication

    Confirm standard SSH connectivity and authentication with GitHub via the container.

    docker exec docker-compose-1 ssh -T git@github.com

    Add the Jekyll Bypass File

    Create an empty .nojekyll file inside your source documentation folder to instruct GitHub Pages to serve the raw HTML files directly without running Jekyll.

    touch ~/pihomelabs/.nojekyll

    Deploy the Documentation

    Run the deployment command using your active socket path to push the built site to your repository's gh-pages branch.

    docker exec mkdocs-mkdocs-1 mkdocs gh-deploy --force
