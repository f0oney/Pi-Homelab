With the self-signed certificates created, we can use these to create our HTTPS connections to the local domains. For this example, we will use our Pihole server block we setup previously under [2. Configuration Files & HTTP], to add on HTTPS capability.

---------------------------------------------------

### Server Block Amendments

Navigate to the server block created earlier via `sudo nano /etc/nginx/sites-available/your.sites`, and add the additional lines:

```bash
server {
    listen 443 ssl; # https port
    listen [::]:80; # used for ipv6
    server_name example.com  www.example.com;

    ssl_certificate /etc/openssl/certificates/user.crt; # Locations of the certs
    ssl_certificate_key /etc/openssl/keys/user.key; # Location of the keys

   location / {

       proxy_pass http://localhost:${PORT};  # Backend server URL/port
       proxy_set_header Host $host;
       proxy_set_header X-Real-IP $remote_addr;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto $scheme;
   }
}
```

- `ssl_certificate` and `ssl_certificate_key` lines are added, so that the certificate crt and key are obtained and used in it's connection.
- `listen 443 ssl` is used in replacement of port 80, as this is the https port.
- `listen [::]:80` is used for ipv6 connections.

### HTTPS Redirect

To redirect http requests to https, we can add the following server block on top:

```bash
server {
    listen 80; # http port
    listen [::]:80; # used for ipv6

    server_name example.com www.example.com;
    return 301 https://example.com/admin;
}
```
### Checking for syntax errors

With the Pihole server block now complete, we can check for syntax errors, before applying the changes:

```bash
sudo nginx -t
sudo systemctl reload nginx
```
