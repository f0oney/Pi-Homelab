To install Pihole, we can use Docker Compose. This will allow us to use a `.yaml` file, which also contains the Unbound DNS container, that can work alongside Pihole.

-------------------------------------------------

### File Structures

As for the location of the file, we will store this via `/home/user/raspberrypi-homelab/pihole-unbound`, as this is the publicly available GitHub repository, and a file we would like to share.

We specifically want the Pihole and Unbound data files to be stored under `PiProject-homelab-data`. This can be specified in the `piholeunbound-compose.yaml` file itself.

We can then copy any files we want to share on our GitHub page to `/home/user/PiProject-homelab`. These files were created under the GitHub branch of my guides, from [2. Project Repository Setup], and an explanation of both folders, and their purposes, can be found here: [3. Shared Repository Files].

### Docker Compose File

The following config is to be entered within the `.yaml` file:

```bash
services:
  pihole:
    container_name: pihole # Can be named anything
    image: pihole/pihole:latest
    ports:
      - "53:53/tcp" # The DNS port
      - "53:53/udp"
      - "591:80/tcp" # 80 is the HTTP port it will listen on, whilst 591 will be the port it directs the traffic too. This is for the Web Interface, and 591 is the port I chose for this.
      - "${PORT}:443/tcp" # The HTTPS ports
    environment:
      TZ: "YOUR_TIMEZONE"
      FTLCONF_webserver_api_password: ${PIHOLE_PASSWORD}  # This points to the .env file, which contains the password it pulls. This is so this .yaml file can be safely shared on GitHub, without exposing my password.
      DNSMASQ_LISTENING: "all"
      PIHOLE_DNS_1: "unbound#53"  # Point to unbound container
    volumes:
      - /home/user/PiProject-homelab-data/pihole:/etc/pihole # Pihole files stored in host raspberrypi-homelab-data, and container will mirror this in /etc/
      - /home/user/PiProject-homelab-data/dnsmasq.d:/etc/dnsmasq.d
    restart: unless-stopped
    networks:
      dns_network:
    cap_add:
      - NET_ADMIN
      - NET_RAW
      - CAP_SYS_NICE
      - CAP_SYS_TIME
    security_opt:
      - seccomp:unconfined
    depends_on:
      - unbound
  unbound:
    container_name: unbound2026050
    image: klutchell/unbound:latest
    volumes:
      - /home/user/PiProject-homelab-data/unbound:/etc/unbound/custom.conf.d # Unbound files stored in host raspberrypi-homelab-data, and container will mirror this in /etc/
    restart: unless-stopped
    networks:
      dns_network:
networks:
  dns_network:
    driver: bridge
```

- Check comments with # for short descriptions

### .env File

**Note**: For the password in this configuration, it is finding and using a created variable. We can just set a plain text password, but we can use this instead if sharing this config on GitHub, so it is hidden. To do this, create a new file in the same location named `.env`, and enter the following in it's file:

```bash
PIHOLE_PASSWORD=INSERT_HERE
```

`INSERT_HERE` can be replaced with the chosen password. `.env` is used, as GitHub is setup to ignore and not pull any `.env` files, as specified in it's `.gitignore` file, under `/home/fooney/raspberrypi-homelab`.

### Deploying the compose file

Once this file(s) have been created, and config lines used above, we can then initiate it's installation via the following command:

```bash
sudo docker compose -f piholeunbound-compose.yaml up -d
```

Wait for the installation to finalise. Once finished, we can check that both the Unbound and Pihole containers are running via `sudo docker ps`.

## Updating Pihole/Unbound

As for all docker containers, please ensure that the containers are updated with the latest image!!

We can check if this is out of date, via the portal itself at the bottom of the page. This will note as **Update Available**. 

Run the following command to pull the latest image, and then stopping and deleting the current containers, before installing again via the compose file:

```bash
docker pull pihole/pihole:latest
docker pull klutchell/unbound:latest
```
