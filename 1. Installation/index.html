    1. Installation

    Nginx is a reverse proxy, which can be used to redirect IP Addresses with different ports, to different local domains setup in Pihole.

    In this case, we have our Raspberry Pi IP 192.168.50.44. In it's current form, each service is hosted in it's own Docker Container. As with my previous configuration of Nginx, this was on bare metal, outside of a Docker Container, but with this setup, it meant that we had to open up random ports for each service.

    For example, as the default port for Pihole is 80, as well as Vaultwarden, we needed to allocate them both different ports via Nginx. This can be quite insecure. As this is all local, the ports and IPs are not open to public view, so it does not present a major threat, but it is still good practise to steer away from this, and rather group all docker containers, including Nginx, into one Docker Network.

    This means that Nginx will point to the container's name, and uses the services default port to push the relevant traffic across, dependent on what local domain is being entered. Example below of this being done on the Nginx Server Block File:

    https://pihole:80

    To proceed with this setup, we can first create a new docker network. Lets call this 'dns_network':

    docker network create -d bridge dns_network
    Docker Compose File

    Once created, we will then need to incorporate this into our Docker Compose file for Nginx. The following file is created, with lines added (This file is placed under ~/raspberrypi-homelab/docker-compose):

    services:
  nginx:
    image: nginx:latest
    container_name: nginx_proxy
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ${NGINX_VOLUME}:/etc/nginx/conf.d:ro
      - ${CERTS_VOLUME}:/etc/openssl/certificates:ro
      - ${KEYS_VOLUME}:/etc/openssl/keys:ro
    networks:
      dns_network:

networks:
  dns_network:
    external: true
    driver: bridge

    A breakdown of the lines:

    networks: - This is the block outside of services. This calls the dns_network, which is specified underneath. external: true - This specifies that the network is already created and available outside of the docker compose file. If not included, the docker compose file will attempt to create the network fresh. driver: bridge - The network mode bridge allows all docker containers that are connected to this network, to create a 'bridge' of communication between them all.

    networks: - This is inside of the services branch. This simply allows for the service to join and use this network.

    ports: - These ports will need to be opened, which are usually just the default ports 80 and 443, which our other docker containers use by default for traffic. If we don't open these ports on Nginx, then no traffic will flow through to the other containers, being completely blocked off.

    volumes: - The Certs and Keys volumes will contain our OpenSSL certs/keys, that the Nginx Docker Container will need to grab and read for use in our server block file. The /conf.d is our main configuration folder.

    Deploying the compose file
    sudo docker compose -f nginx-compose.yaml up -d

    Once the above has been ran, we can confirm it has successfully deployed by checking the active containers:

    Docker ps

    We can also check it's logs to check for any errors:

    Docker logs nginx_proxy
    For other Docker Containers going forward

    Now that the Nginx docker container is up and running, connecting to Docker Network dns_network, we will need to ensure that all other docker containers going forward includes this network in their compose files.

    They will simply need the following added:

    services:    
    networks:
      dns_network:

networks:
  dns_network:
    external: true
    driver: bridge

    This will be briefly explained on the installation of the other Docker Containers and any adjustments needed.
