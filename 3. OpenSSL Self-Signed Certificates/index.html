    3. OpenSSL Self Signed Certificates

    OpenSSL is the service we will use to create our certificates, which will allow us to use HTTPS against our local domains. OpenSSL is recommended for self-signed certificates, as noted by Lets Encrypt via their Documentation.

    'Self-Signed' certificates are certificates signed by the creator's own private key, rather then a trusted third-party Certificate Authority. This allows us to complete this completely offline, whilst having the basic encryption needed for our web portals.

    The downside to this setup however, is that we would need to manually download the certificate onto each device, and add to the web browser being used. This means that the certificates are not trusted by anyone else, but for local development, this is fine.

    Installation

    To get started, we can install OpenSSL via the following command:

    sudo apt install openssl

    Folder Structures

    Once installed, we next need to create a folder where we will store the certificates. In this case, I will be creating a folder named openssl under /etc/openssl:

    cd /etc/
mkdir openssl
cd /etc/openssl

    In the folder, we can begin running our commands to create the certificates.

    Creating the Certificates

    Firstly, we will need to create the key for the CA Certificate. This will be named userCA.key. The following command is ran below:

    openssl genrsa -des3 -out userCA.key 4096

    Then, we will need to generate the CA certificate itself with the created CA key, named userCA.crt. This will prompt for the information required for the certificate…

    openssl req -new -x509 -days 3650 -key userCA.key -out userCA.crt

    The info it requests will be as follows:

    • Country Name (2 letter code)
    • State or Province Name
    • City
    • Organisation Name
    • Organisational Unit Name
    • Common Name (e.g. server FQDN or YOUR name)
    • Email Address

    The information does not need to be real, and you can enter fake information, such as a fake name. This is because no public authority checks these.

    Once the CA root certificate is created, we can then proceed with creating the wildcard custom domain certificate. This allows us to use the certificate for any local domains using *.user.local, named user.key:

    openssl genrsa -out user.key 2048

    We will now need to create the config file openssl.cnf, which we are going to use for CSR and signing. The CSR is a Certificate Signing Request, which is a message sent to the CA (Certificate Authority) to apply for a certificate. To create and start the config file, we can run:

    Sudo nano openssl.conf

    Then, the following can be entered in the config file itself:

    [req]
default_md = sha256
prompt = no
req_extensions = req_ext
distinguished_name = req_distinguished_name

[req_distinguished_name]
commonName = *.example.com
countryName = YOUR_COUNTRY
stateOrProvinceName = No state
localityName = No City
organizationName = No Company

[req_ext]
keyUsage=critical,digitalSignature,keyEncipherment
extendedKeyUsage=critical,serverAuth,clientAuth
subjectAltName = @alt_names

[alt_names]
DNS.1=user.local
DNS.2=*.user.local

    We can then use this to create the CSR:

    openssl req -new -nodes -key user.key -config openssl.cnf -out user.csr

    We can finally then sign this with the created CA. The final certificate that we can use will be named user.crt:

    openssl x509 -req -in user.csr -CA userCA.crt -CAkey userCA.key -CAcreateserial -out user.crt -days 1024 -sha256 -extfile openssl.cnf -extensions req_ext

    With the certificates and keys created, we can organise these into sub folders within the OpenSSL folder:

    /etc/openssl/ca_certificates userCA.crt /etc/openssl/ca_keys userCA.key /etc/openssl/certificates user.crt /etc/openssl/keys user.key

    Installing the Certificates

    For us to be able to use these on our devices, we will need to install them on each individual device. As I am using MobaXTerm for accessing the Pi console via SSH, I can simply navigate to the file directory via the file directory tree (found on the left side of the application).

    We want to install the userCA.crt certificate on the device, via /etc/openssl/ca_certificates, by highlighting the file > right-click > press Download.

    Once this is on our machine, we can then share this on other devices by any preferable method. The steps on installing the certificate is slightly different however.

    Windows

    We can simply follow the steps found under #Trusted-Root-CA, on [[Router HTTPS Configuration]]. This will guide you on how to add the certificate to the Trusted Root Certification Authorities.

    Android

    Under the settings, navigate through the following settings:

    1. Click on Security and privacy > More security settings > Install from device storage > CA certificate
    2. Choose Install anyway
    3. Enter your device password or biometrics
    4. Find the file in your storage, and click Done
    Browser

    We can also add it to our browsers, via it's certificate settings. Steps vary depending on browser, but for Firefox, this can be done via:

    1. Click on Privacy and Security
    2. Choose Advanced settings under Connection and software security
    3. Scroll down to Certificates, and choose Manage Certificates
    4. Press Import, and select the certificate stored on your device
