As we're hosting our password manager locally, sometimes, we may lose this data under unfortunate circumstances. Therefore, it is important to backup our password database, so that if anything did happen to the server for example, we have backups readily available.

For the method I am using, I will be setting up Rclone (the same service used for our system file backups) and the `vaultwarden-backup` docker contianer.

----------------------------------------------------------------------

## Updated `vaultwarden-compose.yaml` file
In order to do this for vaultwarden, we will be making use of another docker container. This will be added on to our existing docker compose file for Vaultwarden. The following can be added:

```bash
services:
  vaultwarden:
    image: vaultwarden/server:latest
    container_name: vaultwarden
    restart: unless-stopped
    dns:
      - ${UNBOUND_DOCKER_IP} # To ensure Vaultwarden uses Unbound (Docker IP)
      - ${PI_IP} # Fallback to Pi IP as DNS
    networks:
      dns_network:
    environment:
      DOMAIN: ${DOMAIN}  # enter your domain
      SIGNUPS_ALLOWED: "false"                  # disable after creating your first account
      ADMIN_TOKEN: ${ARGON2_HASH}
    volumes:
      - ${VAULTWARDEN_VOLUME}:/data

  backup:
      image: ttionya/vaultwarden-backup:latest
      container_name: vaultwarden-backup
      restart: unless-stopped
      dns:
        - ${UNBOUND_DOCKER_IP} # To ensure Vaultwarden uses Unbound (Docker IP)
        - ${PI_IP} # Fallback to Pi IP as DNS
      networks:
        dns_network:
      environment:
        # Must match the remote created with rclone config
        RCLONE_REMOTE_NAME: "BitwardenBackup"

        # Directory inside the remote storage
        RCLONE_REMOTE_DIR: "/Vaultwarden Backups/"

        # Run at 02:15 every day
        CRON: "* * * * *"

        # Create one encrypted archive
        ZIP_ENABLE: "TRUE"
        ZIP_TYPE: "7z"
        ZIP_PASSWORD: ${ARGON2_HASH_BACKUP}

        # Keep backups from the last 30 days
        BACKUP_KEEP_DAYS: "30"

        # Optional: use your local timezone
        TIMEZONE: ${TZ}

        # Optional: identify this server in logs and notifications
        DISPLAY_NAME: "vaultwarden"

      volumes:
        - ${VAULTWARDEN_VOLUME}:/bitwarden/data/
        - vaultwarden-rclone-data:/config/

volumes:
  vaultwarden-rclone-data:
    external: true
    name: vaultwarden-rclone-data

networks:
  dns_network:
    external: true
    driver: bridge
```

### Environment Variables
The following variables have been used, and described as so:

#### backup service
The main backup service is used, pulling it's `image`, setting it's `container_name`, and also calling the `dns` server IPs and docker network `dns_network`.
#### RCLONE
`RCLONE_REMOTE_NAME` will be the Rclone connection name that we will be calling from the set volume. 
`RCLONE_REMOTE_DIR` will be the location of the backups within our Cloud Drive. This case being on Proton Drive.
#### CRON
This will set when the backup runs via crontab. Example being running everyday, at 2:30AM:

`0 4 * * *`
#### ZIP
The variable `ZIP_ENABLE` allows the backup to be encrypted, using the other variable `ZIP_TYPE` to set it's file type, and `ZIP_PASSWORD` being the password used to access it.
#### BACKUP_KEEP_DAYS
This singular variable will determine how long the backup exists for, before being removed.
#### Volume
The volume `vaultwarden-rclone-date` is created, and marked as `external`, as it will be already created outside of the docker compose file, with data already setup.

### Volume Creation
To create our volume outside of the Docker Compose File, we can run the following command:

```bash
docker volume create vaultwarden-rclone-data
```

Once it exists as a volume, we can then setup our Rclone configuration. This will allow us to setup what cloud service we will be using:

```bash
docker run --rm -it \
  --mount type=volume,source=vaultwarden-rclone-data,target=/config/ \
  ttionya/vaultwarden-backup:latest \
  rclone config
```

Proceed with the following options:

1. Enter `n` to start a new remote. 
2. This will prompt for a name. I have entered 'ProtonDrive'.
3. We will then need to pick our Cloud Service. Choose `43` for Proton Drive.
4. For this service, enter the email address used for the Cloud Service Login.
5. Choose the option for entering your password to the Cloud Service Account. 
6. Enter the 2FA code tied to your Cloud Service Account (6-digit Code).
7. Do not enter a secret key, or editing the advanced config when prompted.

Once setup, we can simply exit out of the configuration using `q`. To confirm this has been setup correctly, we can run the following:

```bash
docker run --rm -it \
  --mount type=volume,source=vaultwarden-rclone-data,target=/config/ \
  ttionya/vaultwarden-backup:latest \
  rclone config show
```

Once happy, we can then run our compose file. Please ensure that the current vaultwarden container has been stopped and deleted.

```bash
sudo docker compose -f vaultwarden-compose.yaml up -d
```
