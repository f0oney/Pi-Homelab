Next, we want to create our repository on Github. These steps were used to create my public repository **Pi-Homelab** as part of my Raspberry Pi Project, as user f0oney.

----------------------------------------------------------

### GitHub Repository Creation

Firstly, we want to create a new repository via Github. Login to the Github main homepage, and click **New**. This opens the new Github repository page. Fill in the details, and set this to private for the time being.

Repository for the Raspberry Pi Homelab is named **Pi-Homelab**, and linked here: https://github.com/f0oney/Pi-Homelab

Once created, we can then move over to the Raspberry Pi, to create our project repo folder, where we will link this across to the created GitHub Repo.

### Repo folder structure on Server/Device

On your device, under `/home/user/`, we can create a new folder named after your project. For this example, we can user **PiProject**, via the following command:

```bash
sudo mkdir pihomelab
cd /home/home/pihomelab
```

Inside of this folder, we can then run the git command below, to create the repo files:

```bash
sudo git init -b main
```

Once the git files have been created, we can start structuring this repo folder, by adding in the separate folders for each of your services. For me, I have vaultwarden and pihole-unbound that I can add in as sub-folders:

```bash
sudo mkdir -p ~/pihomelab/vaultwarden
sudo mkdir -p ~/pihomelab/pihole
sudo mkdir -p ~/pihomelab/unbound
```
### .gitignore

We can then create a `.gitignore` file, which allows us to specify files we do not want to have show up under our GitHub repository. These can include `.env` files, or `.db` files to name a couple.

```bash
sudo nano .gitignore
```

I have then entered the following file types (* meaning any word used):

`.env`
`*.env`
`*.db`
`*.sqlite`
`*.sqlite-journal`

You can add folders etc, which I have additionally done, to hide the sensitive data and configs.

### Remote Origin

Next step is to add the remote origin, that links to our private repository created in GitHub, via the following:

```bash
sudo git remote add origin git@github.com:username/reponame.git
```

### Stage and Commits

Once satisfied, we then want to stage the current structure and updates done to this project folder:

```bash
git add .
```

This can then be followed by commiting the changes, so that it saves it locally:

```bash
sudo git commit -m "Initial homelab setup and folder structure"
```
- The comment in the speech marks adds a comment on the github page, once the changes have been made.

### Push

We can then finally push these files and changes to the GitHub repository, by using the push command:

```bash
sudo git push -u origin main
```
- This pushes it to the main branch of the repository.
- Command will prompt for github username, but also the github password.
- The Github password will require you to create a Personal Token Key within the Developer settings of GitHub. Recommend generating a classic token key, and then copying this into the console.

Tip: We can add `--force`, if there is already a README folder in, that we are happy with replacing when the pull command is initiated.
