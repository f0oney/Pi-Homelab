Once the containers are installed, we can then proceed on creating the Unbound files. These aren't necessary, due to the container already pre-generating these in the background, but we can create these manually under `~/pihomelab/unbound` if we want to edit and create custom configs. 

These will then mirror over to `/etc/unbound/custom.conf.d`, as directed on the directory setting of Unbound on the `.yaml` file - [[Raspberry Pi/Pihole & Unbound/1. Installation|1. Installation]]. Then, any files mirror'd to `custom.conf.d`, Unbound will pick up, and use over it's default configs.

Firstly, lets ensure the `/etc/unbound/custom.conf.d` folder exists on the system. If not already, cd to `/etc/`, and enter the following commands:

```bash
cd /etc/
mkdir unbound
cd unbound/
mkdir custom.conf.d
```

We will then need to cd over to `~/pihomelab/unbound`, and can create the following files...

### unbound.conf

```bash
sudo nano unbound.conf
```

```bash
server:
    verbosity: 1
    interface: 0.0.0.0 # Listening on all network interfaces, so it can accept traffic coming in from the Docker bridge network 172.x.x.x
    port: 53
    do-ip4: yes
    do-udp: yes
    do-tcp: yes

    # May be set to yes if you have IPv6 connectivity
    do-ip6: yes

    # Use this only when you downloaded the list of primary root servers!
    root-hints: /etc/unbound/custom.conf.d/root.hints

    # Trust glue only if it is within the servers authority
    harden-glue: yes

    # Require DNSSEC data for trust-anchored zones, if no DNSSEC data for an answer,
    # with trust anchors enabled, the zone becomes Bogus
    harden-dnssec-stripped: yes

    # Don't use capitalization randomization
    use-caps-for-id: no

    # Reduce EDNS reassembly buffer size
    edns-buffer-size: 1472

    # Perform prefetching of close to expired message cache entries
    prefetch: yes

    # Min and Max time DNS Records are cached for, in seconds
    cache-min-ttl: 3600
    cache-max-ttl: 86400

    # One thread should be sufficient
    num-threads: 1

    # Ensure kernel buffer is large enough (reduced to avoid permission warnings)
    so-rcvbuf: 400k

    # Respond to queries from local networks only
    access-control: 127.0.0.0/8 allow
    access-control: 10.0.0.0/8 allow
    access-control: 172.16.0.0/12 allow
    access-control: 192.168.0.0/16 allow

    # Ensure privacy of local IP ranges
    private-address: 192.168.0.0/16
    private-address: 169.254.0.0/16
    private-address: 172.16.0.0/12
    private-address: 10.0.0.0/8
    private-address: fd00::/8
    private-address: fe80::/10

```

### dnsmaq.d

We can also configure and create our custom configuration file for `dnsmasq`. This is located in `~/pihomelab/dnsmaq.d`, which we can cd into, and run command `sudo nano 02-lan-access.conf`, entering the following config:

```bash
# Allow all interfaces
listen-address=0.0.0.0
bind-interfaces
domain-needed
bogus-priv
EOF
```

### resolv.conf

To prevent DNS leaks, we can set `resolv.conf` to use Pihole, and also ensure it is immutable so that we prevent the DHCP from changing it:

```bash
echo "nameserver 127.0.0.1" | sudo tee /etc/resolv.conf
sudo chattr +i /etc/resolv.conf
```

### dhclient

We can set in the `dhclient.conf`file to point to domain server 127.0.0.1:

```bash
sudo nano /etc/dhcp/dhclient.conf

#Add in the file
supersede domain-name-servers 127.0.0.1;
```

### Docker DNS

We will also need to configure the Docker DNS via the `daemon.json` file. To do this, create or edit `/etc/docker/daemon.json`

```bash
sudo nano /etc/docker/daemon.json

#Add in the file
{
	"dns": ["127.0.0.1"]
}
```
