# 1. Installation

Nginx is a reverse proxy. It receives every request on ports 80 and 443, and forwards it to the right service based on the local domain entered (set up as local DNS records in Pihole).

Each service on the Raspberry Pi runs in its own Docker container. My previous Nginx setup ran on bare metal, outside Docker, which meant every service had to publish its own port on the Pi. For example, Pihole and Vaultwarden both default to port 80, so each needed a different host port. As this is all local, the ports aren't open to the public, but publishing one port per service is untidy and exposes more than needed.

Instead, Nginx and the other containers share one Docker network. Nginx reaches each container by its **container name** on the service's default port, so only Nginx needs ports 80 and 443 published on the Pi. For example, in a server block:

```nginx
proxy_pass http://pihole:80;
```

Inside the shared network, containers can all use port 80 without clashing. A clash only happens when two containers try to *publish* the same port on the host.

---

### Docker Swarm and Network

Nginx runs as a **Docker Swarm service** on the Raspberry Pi, which is the swarm manager. Running it as a service lets it join the `swarm_network` overlay network, which spans every node, so it can also reach containers on other servers (e.g. Proxmox).

Creating the swarm and the `swarm_network` network is covered in the **Portainer SWARM Setup** guide, so make sure you're not duplicating networks. For reference, the network is created with:

```bash
# Creating a new external network for Portainer and all other containers to use
docker network create --driver overlay --attachable swarm_network
```

`--attachable` is required so that normal `docker compose` containers, not just swarm services, can join the network.

### Service File

The service file is saved as `nginx-service.yaml` under `~/pihomelab/docker-compose`:

```yaml
version: "3.8"
services:
  nginx:
    image: nginx:1.27  # pinned version, so updates are deliberate
    ports:
      # mode: host passes the real client IP to Nginx.
      # Without it, every request appears to come from the swarm ingress network.
      - target: 80
        published: 80
        protocol: tcp
        mode: host
      - target: 443
        published: 443
        protocol: tcp
        mode: host
    volumes:
      - ${NGINXVOLUME}:/etc/nginx/conf.d:ro
      - ${CERTSVOLUME}:/etc/openssl/certificates:ro
      - ${KEYSVOLUME}:/etc/openssl/keys:ro
    networks:
      - swarm_network
    deploy:
      replicas: 1
      placement:
        constraints:
          - node.role == manager # run on the Raspberry Pi
      restart_policy:
        condition: on-failure

networks:
  swarm_network:
    external: true
```

A breakdown of the lines:

- `ports:` publishes 80 (HTTP) and 443 (HTTPS) on the Pi. These are the only ports clients need. Containers behind Nginx don't need their web ports published at all.
- `volumes:` mounts the folders Nginx reads from. `conf.d` holds the server block files, and the certificates and keys folders hold the OpenSSL files created in **3. OpenSSL Self Signed Certificates**. All are read-only (`:ro`).
- `networks:` (inside the service) joins Nginx to `swarm_network`.
- `networks:` (top level): `external: true` tells Docker the network already exists, so it doesn't try to create it. No `driver` line is needed for an external network.
- `deploy:` holds swarm-only settings: one copy of Nginx, kept on the manager node (the Pi), restarted if it fails. If more manager nodes are added later, use `node.hostname == [PI_HOSTNAME]` to pin it to the Pi specifically.

### Environment Variables

The volume paths are set in a `.env` file in the same folder. The names must match the service file exactly:

```bash
NGINXVOLUME=/home/[USER]/pihomelab/nginx
CERTSVOLUME=/etc/openssl/certificates
KEYSVOLUME=/etc/openssl/keys
```

Use full paths rather than `~`, with no spaces around `=`.

### Shared Nginx Settings

Create `00-websocket.conf` in the Nginx config folder (`~/pihomelab/nginx`, the `NGINXVOLUME` folder), alongside `serverblock.conf`. Every server block can then use these settings:

```nginx
# Lets server blocks pass WebSocket connections through
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

# Docker's internal DNS, used to look up container names
resolver 127.0.0.11 valid=30s ipv6=off;
```

> **Note:** This is an Nginx file, so it goes in the Nginx config folder, not Pihole's `dnsmasq.d` folder. Define the `map` and `resolver` only once. If `serverblock.conf` already has them, remove them from there.

> **Tip:** With a plain `proxy_pass http://pihole:80;`, Nginx looks the container name up once at startup, and **refuses to start** if that container isn't running. Using a variable makes Nginx look it up per request through the `resolver` above, so one stopped container doesn't take down every site:
> ```nginx
> set $upstream pihole;
> proxy_pass http://$upstream:80;
> ```

### Deploying the Service

If the old standalone Nginx container is still running, remove it first, as it holds ports 80 and 443:

```bash
sudo docker compose -f nginx-compose.yaml down
```

`docker stack deploy` does **not** read `.env` files the way `docker compose` does. If the variables aren't loaded, the service deploys with empty volumes, and Nginx starts with no config, certificates or keys, so no domains work.

Load the variables into the shell first, then deploy. From `~/pihomelab/docker-compose`:

```bash
set -a; . ./.env; set +a
docker stack deploy -c nginx-service.yaml proxy
```

This creates the service `proxy_nginx`. Running the same commands again later updates the existing service in place.

### Checking the Service

```bash
# Is it running, and on which node? (should be the Pi)
docker service ps proxy_nginx

# Did it get the right folders? Each line should show a full path
docker service inspect proxy_nginx --format '{{range .Spec.TaskTemplate.ContainerSpec.Mounts}}{{.Source}} -> {{.Target}}{{"\n"}}{{end}}'

# Logs. Look for "Configuration complete; ready for start up" with no [emerg] lines after it
docker service logs --tail 20 proxy_nginx

# Test the config files
docker exec $(docker ps -q -f name=proxy_nginx) nginx -t
```

After changing any config file, reload with:

```bash
docker service update --force proxy_nginx
```

To test a domain from the Pi (`-L` follows redirects, e.g. Pihole's `/admin` → `/admin/login`):

```bash
curl -kIL https://pihole.example.com/admin
```

### For Other Docker Containers Going Forward

Any container Nginx proxies to must be on `swarm_network`. Add this to its compose file:

```yaml
services:
  myservice:
    container_name: myservice # the name Nginx uses in proxy_pass
    networks:
      - swarm_network

networks:
  swarm_network:
    external: true
```

Its web port no longer needs publishing on the host. For Pihole, keep publishing port `53` (DNS), but remove `80:80`, as the web interface is now reached through Nginx and port 80 belongs to Nginx.

`swarm_network` is the only network needed. Containers on it can also reach each other, so Pihole talks to Unbound over it too. Pihole's upstream field needs an IP rather than a container name, so set it to Unbound's IP on `swarm_network`:

```bash
docker inspect unbound --format '{{(index .NetworkSettings.Networks "swarm_network").IPAddress}}'
```

This IP can change if the Unbound container is recreated. To keep it fixed, give Unbound an `ipv4_address` under `swarm_network` in its compose file. This only works if the network was created with a set subnet, e.g. `--subnet [SUBNET]`.

Any adjustments needed for specific services are covered in their own installation notes.

### Troubleshooting

- **No domains work, but the logs show no errors:** the service was probably deployed with empty variables. Check the mounts with the `docker service inspect` command above, and redeploy with the variables loaded.
- **"This site can't be reached" in the browser, but curl works on the Pi:** the device isn't resolving the domain through Pihole. Check for a VPN, or the browser's "Secure DNS" setting, both of which bypass Pihole.
- **502 Bad Gateway on one domain:** Nginx is fine, but it can't reach that container. Make sure the container is on `swarm_network`.
