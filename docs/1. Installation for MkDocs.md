MKDocs is used as a site generator, which I will be using to host my homelab documentation, which can be shared via GitHub Pages under my Repo. With MKDocs, we will be adding the Material Theme alongside this, which is a popular site theme used on MKDoc sites.

For this deployment, we will be using Docker Compose. This setup will allow us to easily manage our project documentation, and check over its contents before moving over to GitHub Pages.

### Prerequisites
The container uses the host's SSH agent so that `mkdocs gh-deploy` can push to GitHub. For this to work, the `SSH_AUTH_SOCK` environment variable must reach Docker Compose.

By default, `sudo` resets the environment, which drops `SSH_AUTH_SOCK` and changes `HOME` to `/root`. It is recommended to add your user to the `docker` group and run Docker commands without `sudo`:

```bash
sudo usermod -aG docker $USER
```

Log out and back in for the group change to take effect. If you would rather keep using `sudo`, preserve both variables on each command instead:

```bash
sudo --preserve-env=SSH_AUTH_SOCK,HOME docker compose ...
```

### File Structure
Before we set up and run our Compose file, we first need to set up our folders where MKDocs will be installed.

For the main location of the MKDocs folder, I will be creating this under `~/pihomelab`. This is also the root of the GitHub repository, so it holds the `.git` folder.

In this folder, we can create our configuration file `mkdocs.yml`, and enter the following starter config:

```yaml
site_name: My Docs

nav:
  - Home: index.md
  - About: about.md

theme:
  name: 'material'
```

We can also create sub-folder `docs`, where all our `.md` files will be stored.

The finished folder will look like this:

```
~/pihomelab
├── .env                  # Local values, never committed
├── .gitignore
├── docs/
├── mkdocs.yml
└── mkdocs-compose.yaml
```

### SSH Agent Setup
SSH agent sockets normally live at a random, temporary path (e.g. `/tmp/ssh-XXXXXXXXXXXX/agent.XXXXX`) that is deleted when the SSH session ends. If a container is created with that path, it will fail to start once the session is gone (see Troubleshooting below).

To avoid this, we run the agent at a fixed path inside a dedicated folder, and mount that folder into the container rather than the socket file itself. Add the following to the end of `~/.bashrc`:

```bash
# SSH agent at a fixed socket path (used by the MKDocs container)
export SSH_AUTH_SOCK="$HOME/.ssh-agent/agent.sock"
mkdir -p "$HOME/.ssh-agent" && chmod 700 "$HOME/.ssh-agent"
ssh-add -l >/dev/null 2>&1
if [ $? -eq 2 ]; then
  # Exit code 2 = no agent listening on the socket, so start a new one
  rm -f "$SSH_AUTH_SOCK"
  eval "$(ssh-agent -a "$SSH_AUTH_SOCK" -s)" >/dev/null
fi
```

Reload the shell and add your GitHub key to the agent:

```bash
source ~/.bashrc
ssh-add ~/.ssh/id_ed25519
ssh-add -l    # should list your key
```

The agent keeps running between SSH sessions, so new logins will reuse it. After a reboot, run `ssh-add` again to reload the key.

Make sure GitHub is in the host's `known_hosts` file, as this is mounted into the container so the push isn't blocked by a host key prompt:

```bash
ssh -T git@github.com
```

### Docker Compose File
For the compose file, we will be creating this under the `~/pihomelab` folder, named `mkdocs-compose.yaml`. The following configuration will be used:

```yaml
services:
  mkdocs:
    image: squidfunk/mkdocs-material
    container_name: mkdocs
    dns:
      - ${UNBOUND_DOCKER_IP}
      - ${PI_IP}
    networks:
      swarm_network:
    volumes:
      - ${MKDOCS_VOLUME}:/docs
      - ${HOME}/.ssh/known_hosts:/root/.ssh/known_hosts:ro
      - ${HOME}/.ssh-agent:/ssh-agent-dir
    environment:
      - SSH_AUTH_SOCK=/ssh-agent-dir/agent.sock
    stdin_open: true
    tty: true

networks:
  swarm_network:
    external: true
```

Notes on this configuration:
- **No private keys in the container.** Only `known_hosts` is mounted from `~/.ssh`; authentication is handled by the agent.
- **The agent folder is mounted, not the socket.** If the agent isn't running, the container still starts (pushes just won't authenticate until it is).
- **`swarm_network` is external**, so `driver` and `attachable` are not set here. Those only apply when Compose creates the network itself.
- **`${HOME}` is taken from your shell**, so it does not need adding to `.env`. Run Compose as your own user (see Prerequisites) so it points to your home folder rather than `/root`.

The other variables are set in a `.env` file in the same folder as the compose file. Replace the placeholders with your own values:

```bash
MKDOCS_VOLUME=/home/<user>/pihomelab
UNBOUND_DOCKER_IP=<unbound container IP>
PI_IP=<raspberry pi IP>
```

Do **not** set `SSH_AUTH_SOCK` in `.env`. It is handled by `~/.bashrc` and the compose file.

As `~/pihomelab` is the repository, make sure `.env` is never pushed to GitHub by adding it to `.gitignore`:

```bash
echo ".env" >> ~/pihomelab/.gitignore
```

If `.env` was committed in the past, remove it from tracking with `git rm --cached .env`, then commit. Earlier commits will still contain it, so treat any values in it as public.

Inside `~/pihomelab`, we can run the compose deployment command:

```bash
cd ~/pihomelab
docker compose -f mkdocs-compose.yaml up -d
```

We can confirm the container can see the agent and authenticate with GitHub:

```bash
docker exec -it mkdocs ssh-add -l
docker exec -it mkdocs ssh -T git@github.com
```

### Updating MKDocs
As for all docker containers, please ensure that the containers are updated with the latest image!!

From `~/pihomelab`, pull the latest image and recreate the container in one step:

```bash
docker compose -f mkdocs-compose.yaml pull
docker compose -f mkdocs-compose.yaml up -d
```

Compose will stop, remove and recreate the container only if the image has changed.

### Troubleshooting
**Error: `error mounting "/tmp/ssh-XXXXXXXXXXXX/agent.XXXXX" to rootfs at "/ssh-agent" ... not a directory`**

This happens on older versions of this setup, which mounted `$SSH_AUTH_SOCK` directly as a file. The container saved a temporary socket path from a previous SSH session; once that session ended, Docker recreated the missing path as a directory and could not mount it onto the `/ssh-agent` file inside the container.

To fix:
1. Check the stale path the container is using:
   ```bash
   docker inspect mkdocs --format '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{"\n"}}{{end}}'
   ```
2. Remove the empty directory Docker created (only if it is an empty directory, not a live socket), using the path shown above:
   ```bash
   sudo rm -rf /tmp/ssh-XXXXXXXXXXXX
   ```
3. Apply the SSH Agent Setup and compose file above, then recreate the container. `docker start` or `docker compose start` will reuse the old config, so it must be recreated:
   ```bash
   docker compose -f mkdocs-compose.yaml down
   docker compose -f mkdocs-compose.yaml up -d --force-recreate
   ```
