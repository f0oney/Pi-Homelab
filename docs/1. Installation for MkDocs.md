MKDocs is used as a site generator, which I will be using to host my homelab documentation, which can be shared via GitHub Pages under my Repo. With MKDocs, we will be adding the Material Theme alongside this, which is a popular site theme used on MKDoc sites.

For this deployment, we will be using Docker Compose. This setup will allow use to easily manage our project documentation, and check over it's contents before moving over to GitHub Pages. 

### File Structure
Before we setup and run our Compose file, we first need to setup our folders where MKDocs will be installed. 

For the main location of the MKDocs folder, I will be creating this under `~/pihomelab`.

For the `mkdocs` folder, we can create our configuration file `mkdocs.yml`, and enter the following starter config:

```bash
site_name: My Docs

nav:
  - Home: index.md
  - About: about.md

theme:
  name: 'material'
```

We can also create sub-folder `docs`, where all our `.md` files will be stored.

### Docker Compose File
For the compose file, we will be creating this under the parent `mkdocs` folder, named `mkdocs-compose.yaml`. The following configuration will be used:

```bash
services:
  mkdocs:
    image: squidfunk/mkdocs-material
    ports:
      - "8000:8005" # Uses port 8000, to avoid conflicts with 80
    dns:
      - ${UNBOUND_DOCKER_IP} # To ensure Vaultwarden uses Unbound (Docker IP)
      - ${PI_IP} # Fallback to Pi IP as DNS
    volumes:
      - ~/pihomelab:/docs
    stdin_open: true
    tty: true
```

Inside `mkdocs`, we can run the compose deployment command:

```bash
sudo docker compose -f mkdocs-compose.yaml up -d
```

### Updating MKDocs
As for all docker containers, please ensure that the containers are updated with the latest image!!

Simply run the command below to pull the latest image, and then stop the container, delete the container, and reinstall it again from the `compose.yaml` file:

```bash
docker pull squidfunk/mkdocs-material
```
