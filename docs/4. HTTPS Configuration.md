# 4. HTTPS Configuration

With the self-signed certificates created, we can use them to set up HTTPS connections to our local domains. For this example, we will add HTTPS to the Pihole server block we set up previously.

---

Open the server block created earlier with `nano ~/pihomelab/nginx/serverblock.conf`, and add the following:

```nginx
server {
    listen 443 ssl; # https port
    listen [::]:443 ssl; # used for ipv6
    server_name example.com www.example.com;

    ssl_certificate /etc/openssl/certificates/user.crt; # location of the certs
    ssl_certificate_key /etc/openssl/keys/user.key; # location of the keys

    location / {
        proxy_pass http://pihole:80; # Backend container name/port
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

`ssl_certificate` and `ssl_certificate_key` tell Nginx where to find the certificate and key for the connection. These paths are inside the container, mounted from the `CERTSVOLUME` and `KEYSVOLUME` folders set in `.env`.

`listen 443 ssl` replaces port 80, as 443 is the HTTPS port.

`listen [::]:443 ssl` does the same for IPv6 connections. Both lines need `ssl`, otherwise that listener serves plain HTTP.

To redirect HTTP requests to HTTPS, add the following server block above it:

```nginx
server {
    listen 80; # http port
    listen [::]:80; # used for ipv6

    server_name example.com www.example.com;
    return 301 https://example.com/admin;
}
```

With the Pihole server block now complete, check for syntax errors before applying the changes:

```bash
docker exec $(docker ps -q -f name=proxy_nginx) nginx -t
docker exec $(docker ps -q -f name=proxy_nginx) nginx -s reload
```

For the other server blocks set up for the Raspberry Pi services, see the **Server Block Service Examples** section.
