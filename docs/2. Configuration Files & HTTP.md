# 2. Configuration Files & HTTP

To begin configuring Nginx, we need to understand its file structure. In the Nginx service file, the volume `/etc/nginx/conf.d` points at a folder in our home directory, which for me is `~/pihomelab/nginx` (the `NGINXVOLUME` path in `.env`). The main Nginx configuration file, `nginx.conf`, already exists inside the container under `/etc/nginx`. We won't see or need to edit it, as it automatically loads every `.conf` file in `conf.d`.

Any additional config files, mainly our proxy server block file, are added to the folder set in the volume, which the Nginx container reads from.

For this setup, we only need to create a `.conf` file containing our server block proxy configuration. CD into your chosen folder and create the `.conf` file, choosing a name that suits you. My file is named `serverblock.conf`.

```bash
cd ~/pihomelab/nginx
nano serverblock.conf
```

> **Note:** Files must end in `.conf`, otherwise Nginx ignores them. Creating them without `sudo` keeps them owned by your user, so they can be edited later without permission errors.

##### Server Block Example

For a basic HTTP setup for our Pihole service, we can use the following template:

```nginx
server {
    listen 80;
    server_name example.com www.example.com; # Replace with your domain

    location / {
        proxy_pass http://pihole:80; # Backend container name/port
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

On the `proxy_pass` line, we only need to give `pihole`, the name of the Docker container, rather than an IP address. Port 80 is added, as this is the default port Pihole uses. This works because Nginx and Pihole are both on `swarm_network`.

> **Tip:** As covered in **1. Installation**, using `set $upstream pihole;` with `proxy_pass http://$upstream:80;` stops Nginx failing to start if the Pihole container isn't running.

With the lines added, save the file and test the configuration for syntax errors. Nginx runs as the swarm service `proxy_nginx`, so the command is run inside its container with `docker exec`:

```bash
docker exec $(docker ps -q -f name=proxy_nginx) nginx -t
```

If all is good, reload Nginx to apply the changes:

```bash
docker exec $(docker ps -q -f name=proxy_nginx) nginx -s reload
```

If the reload doesn't pick up the changes, restart the service instead:

```bash
docker service update --force proxy_nginx
```
