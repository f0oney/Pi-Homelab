To start setting up our reverse proxy, we will need to create a new configuration file, that will host our setup. This is found under `/etc/nginx/sites-available`.

Instead of editing the default config file, we instead want to create a new server block file where we can add on our related proxy settings.

-------------------------------------------------------

### Configuring the server blocks

First, create a new file, preferably named the domain (e.g. user.local) in `/etc/nginx/sites-available`

```bash
cd /etc/nginx/sites-available
sudo touch your.sites
```

We can then edit the file:

```bash
sudo nano your.sites
```

And paste the following template, and replace parameters accoringly:

```bash
server {
	listen 80;
	server_name example.com www.example.com http://www.example.com; #Replace with your domain/IP           
	location / {
		proxy_pass http://localhost:3000; #Backend server URL/port           
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;           
        proxy_set_header X-Forwarded-For 
        $proxy_add_x_forwarded_for;           
        proxy_set_header X-Forwarded-Proto $scheme;       
    }   
}
```

Press CTRL + S to save the file.

### Activating the server block

To activate the server block, we want to create a symlink from `sites-available`, where the server block file sits, to `sites-enabled`. This is because `sites-available` isnt our active files for the proxy, but anything in `sites-enabled` is.

```bash
sudo ln -s /etc/nginx/sites-available/example.com /etc/nginx/sites-enabled/
```

### Disabling the landing page

Once created, we can also go ahead and disable the default nginx landing page, if not needed (optional).

```bash
sudo unlink /etc/nginx/sites-enabled/default
```

### Testing it's configuration

We can then test the nginx configuration for any syntax errors:

```bash
sudo nginx -t
```

If all good, we can then reload nginx to apply the changes:

```bash
sudo systemctl reload nginx
```
